# 1차 스프린트 합의사항

기준일: 2026-10-12 (Asia/Seoul). 이 문서는 1차 구현과 시연에 적용하는 합의사항을 기록합니다.

## 구현·산출물 기준

- 로그인과 보상처리결과 목록·검색·초기화·상세·로그아웃을 1차 업무 범위로 한다.
- 로그아웃 후 정식 controller 목록/상세 URL 요청은 로그인 화면으로 이동한다.
- root/index/main, cmd 없는 진입, 잘못된 cmd, 한쪽 날짜, 없는 상세 번호도 확인한다.
- 업무 흐름·용어·ERD 및 FrontController/Factory/Action/DAO·VO 구성을 유지한다.
- 클래스 다이어그램은 변경하지 않는다. 클래스·인터페이스·필드·메서드 구성을 바꾸는 구조 확장은 2차에서 설계와 구현을 함께 검토한다.
- 초기 UI 프로토타입과의 차이는 허용한다. 불필요한 메뉴·레이아웃 재설계나 발표자료 자동 편집은 하지 않는다.
- 스크롤바가 없는 화면에도 공간을 확보해 화면 전환 시 가로 위치가 바뀌지 않게 한다.

현재 요청 흐름은 `FrontController → ActionFactory → Action 구현체 → DAO·VO`다. DAO는 DBCP·Query를 사용한다. 별도 Service 계층은 구현돼 있지 않다. 직접 JSP 접근 보호용 Filter를 1차에 추가하지 않는다.

## 클래스 다이어그램·단위테스트 대조

최초 dev `396f75b1497602df2719597d2c216d43a3c030da`와 보완 병합 dev `b3187b569ff8cb90278376cdb5d06eb1b17bd9a8`를 컴파일해 `javap -private`로 비교했다. 테스트·유틸을 포함한 Java 29개 클래스 목록과 private/public 필드·메서드 선언이 모두 동일하다.

단위테스트는 로그인 2개·목록 2개·상세 21개, 총 25개 구성·이름을 유지하며 25개 모두 통과했다. 상세 전체 흐름 테스트의 날짜 기대값 2곳만 기존 SQL의 `YYYY-MM-DD` 출력에 맞췄다. 기존 캡처를 최신 main 또는 최종 배포 환경의 새 실행 증빙으로 표기하지 않는다.

DB 연동 테스트는 저장소 밖 별도 검증 런타임에 기존 로컬 DB 접속 설정을 적용해 실행했다. 저장소 팀 DB 설정은 유지했다. 팀 DB 접속 환경의 실행 검증은 별도로 필요하다. 자동 CI 통과 또는 main에서 새로 실행한 결과로 간주하지 않는다.

main 병합 커밋 `f9c9a43aba6563ae6b9f4617cdb83f6f96300f3f`는 위 dev와 파일 내용이 전체 동일하다. PR 승인은 리뷰 상태 변경이며, main 반영은 실제 병합 후 이뤄진다. 웹 서버 배포는 별도 단계다.

## 로컬 자료·DB·기록 정책

- 기존 로컬 수정·미추적 파일·stash는 보존하고 별도 작업 폴더에서 검증한다.
- 팀 DB 설정을 유지하며 개인 접속 설정·비밀번호·로컬 환경 파일은 저장소와 PR에 포함하지 않는다.
- PR·보고서에는 개인 이름과 불필요한 배경을 넣지 않는다.
- main/dev 직접 push나 자동 승인·자동 병합으로 리뷰 절차를 대체하지 않는다.
- 시연 기준 전체 SHA, 작업 폴더, 검증 환경과 결과를 기록한다. 로컬 절대 경로는 로컬 기준 기록에 보관한다.
