# 2차 스프린트 후속 작업

기록일: 2026-10-12. 1차 스프린트는 제출한 클래스 다이어그램의 클래스·인터페이스·필드·메서드 구성을 유지한다.

## 직접 JSP 접근 보호

- 1차 시연의 정식 업무 진입은 `/controller?cmd=...`이다. 기존 FrontController의 로그인 검사와 로그아웃 후 목록/상세 controller 접근 차단을 유지한다.
- `/view/compensationResultList.jsp`, `/view/compensationResultDetail.jsp` 직접 접근까지 보호하는 Filter 추가는 2차 스프린트로 이관한다.
- 1차 보완 PR에서 추가했던 `CompensationViewFilter`는 제거했다. 직접 JSP 접근이 보호된다고 설명하거나 해당 검증을 통과로 표시하지 않는다.
- 2차 작업 시 기존 클래스 다이어그램·요청 흐름을 먼저 갱신하고 팀 리뷰를 거친다. Filter와 JSP의 WEB-INF 배치 등 대안을 검토해 방식을 결정한다.
- 검증: 비로그인/로그아웃 후 직접 JSP 요청 차단, 로그인 상태의 정식 controller 이동, 검색조건·신청번호 유지, 정상 forward의 반복 이동 방지, 뒤로가기·캐시 접근 정책.

## 구조 변경 관리

- 1차의 `ActionFactory.getAction(String)` 선언과 Query 상수 목록은 기존 구성으로 복원한다.
- Factory의 SQL 예외 전달 방식 변경과 Query 조건 상수 분리는 2차에서 설계도·예외 응답 정책·검증 범위를 함께 검토한다.
- 1차의 한쪽 날짜 검색은 기존 DAO 메서드 내부 처리로 보완하며 공개 필드·메서드는 추가하지 않는다.

## 1차 시연 영상 인계 조건

- 최종 파일은 실제 화면 녹화 **MP4**로 제공한다. 정지 이미지/GIF를 시연 영상으로 대체하지 않는다.
- 일반 플레이어에서 재생·일시정지·앞뒤 탐색이 가능해야 한다. 웹에 제공한다면 `<video controls>`를 사용한다.
- 호환성을 위해 MP4/H.264, yuv420p, faststart를 사용하고 음성이 있으면 AAC를 사용한다.
- 승인·병합된 최신 main 전체 SHA와 촬영 기준을 기록하고, 실제 외부 웹 URL·주소창·브라우저 창 테두리를 노출한다.
- 로그인 실패/성공→목록→검색/초기화→상세→로그아웃→controller 목록/상세 재접근 차단을 촬영한다. 직접 JSP 보호는 2차 예정으로 명시한다.
- 완성 MP4의 메타데이터·재생시간·시나리오별 타임스탬프를 확인하고 실제 재생/일시정지/탐색을 검증한다.
- 제출 발표자료의 시연 영역에는 실제 MP4를 재생할 수 있는 플레이어/영상으로 삽입하고 로컬 파일도 함께 보관한다.
